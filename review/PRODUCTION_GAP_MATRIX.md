## Top launch blockers

1. **No backend exists.** There is no Supabase project or Vercel project, and the migration has never been applied to a real Supabase. The adapter has never run inside the UI.
2. **No authentication UI or session handling.** Roles are mocked, the contract can't express per-event roles, and there is no coordinator invite flow.
3. **Guest-link abuse protection is unverified.** It depends on Supabase forwarding the client IP header. CGNAT and guessable slugs need an edge rate limit.
4. **Privacy and legal.** Guest phone numbers (third-party personal data) need a PDPL legal review, a hosting-region decision, a privacy notice and a retention policy before real data is loaded.
5. **Event-day resilience.** There's no gate offline queue, no real QR camera scanning, and no error reporting or backups. A tested restore and a monitoring path are required before the first real event.
